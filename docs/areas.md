# 新しい町(エリア)の設計(おすすめ案)

面パック(チャプター)が増えても、町づくりに「次の楽しみ」が続くようにする。
急かさない・罰しない・確率の報酬なし(ガチャ無し)は守る。

## 決めたこと(おすすめ案)
| 項目 | 方針 | 理由 |
|---|---|---|
| エリアの単位 | **1チャプター = 1エリア**(60面ごと)。チャプターをクリアすると新エリアが開く | 面パックの仕組みを使い回せる。新しい仕組みを増やさない |
| 町は別々 | エリアごとに**別の町**(マス・建物・こびとは独立)。コインは共通 | 「新しい町を一から育てる」楽しみ。進行が混ざらない |
| 行き来 | 町の画面上部の切替で、開いたエリアを**自由に行き来** | 戻れる=罰しない |
| 建物 | **全エリアで同じ20種を使い回す**。見た目は背景(エリアの地面)と季節で変える | 画像の追加が最小。20建物×3段階の画像は共通 |
| 新規画像 | エリアごとに**町の背景1枚**(+任意で入口の飾り1枚)だけ | 制作負担を増やさない。画像が無ければ今の背景で代用 |
| 解放 | 前のエリアの全面クリア。購入では解放しない(面パックの `requires` は別枠のまま) | 課金で町を急かさない |
| 収入 | 変えない(初回クリア20+★、毎日の贈り物)。新エリアは最初のコインが少なくても建てられる安い建物から | 収入設計を崩さない |
| 季節 | 今の「通し番号で5季節を循環」を、エリアごとの面番号に変えない(通しのまま) | 既存の挙動を保つ |

## データ(案)
- `assets/town/areas.json`: `{"areas":[{"id":"village","pack":"main","background":"area_village"},{"id":"meadow","pack":"extra1","background":"area_meadow"}]}`
- 町の保存: `town` キーを `town.<areaId>` に分ける。既存の保存(`town`)は最初のエリア `village` に引き継ぐ(移行あり)。
- 町の画面は、いまのエリアの `TownState` を見せる。ウィジェットは最後に見ていたエリアの絵を出す。

## 実装の順
1. `areas.json` と `AreaInfo`、保存の移行(既存の `town` → `town.village`)、テスト。
2. 町の画面に切替(エリアが1つなら出さない)、解放条件と文言(ja/en)。
3. 背景画像の台帳(`art_manifest.json`)に `area_*` を追加し、画像セッションへ依頼文を出す。

## 決めてほしいこと(任意)
- エリアの名前と雰囲気(仮: 「はじまりの村」「ひだまりの草原」…)。
- 背景画像を作るか(無くても動く)。
