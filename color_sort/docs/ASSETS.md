# 素材(AI画像)の作り方・納品ルール

画像は別途AIで作る。コードは画像を **ID でのみ**参照し、未配置の間は仮の図形で動く。
必要な素材・サイズ・透過は `assets/art_manifest.json`(台帳)が正。

```
dart run tool/check_assets.dart            # 配置済みの画像を検査(未配置は許容)
dart run tool/check_assets.dart --strict   # リリース前: 必須の未配置も失敗
```

## 画像にしない(コードで描く)もの

- **色の記号・数字**(色覚対応の要)。画像に焼き込むと差し替えで失われる。塗り色もコード側(`palette.dart`)
- **文字全般**(多言語のため)。画像内に文字を入れない。ロゴのみ例外

## AI画像のルール(統一感のため)

1. シリーズ共通の指示文(スタイル・色味・線の太さ)を1つ決め、全素材で使い回す。かわいい・ゆっくり・のどか。
2. 背景は透過PNG(台帳の `transparent: true`)。AIが背景を塗る場合は抜き作業が必要
3. 縁に余白を残す(切れた絵は描画時に不自然になる)
4. 容器は中身(色玉)が見えるよう、手前画像は半透明に
5. 盤面の色玉と競合しないよう、背景は彩度・コントラストを抑える
6. 動物は使わない(競合が多いため)。住人は「こびと」。見た目・数・役割は未決(台帳では仮に3種)
7. 権利: 利用した生成サービス(Leonardo、Nano Banana=Google の生成AI)の商用利用規約・出力の扱いと、生成物が既存キャラに酷似していないかを確認する。ユーザーの回答は「問題ない」(2026-10-20)。確認した規約の版と日付は、素材の台帳(Drive)に残す

## 建物は20種×3段階(60状態)

設計書(町づくり設計 v0.1): 建物は20種(拡張なし)、各建物は3段階で見た目が育つ。台帳に60状態を持つ。

- **名前**: `<ID>_s1.png`〜`_s3.png`(例 `mushroom_house_s2.png`)。ID は台帳の20個(すまい5・しぜん5・くらし5・めいしょ5)。名前と絵柄は仮だが ID は固定(テストで検査)
- **大きさ**: 512x512・透過。町のマスの形(正方形か縦長か)は未決のため、**背景を透明にした1024pxの元画像(マスター)を Drive に残す**(作り直せるように)
- **段階の組は、同じ縮尺・同じ地面の線・同じ台座の中心にそろえる**(`prep_stages.py`)。1枚ずつ枠に収めると、縦に伸びる3段階目だけ縮んで「育ったのに小さい」見た目になる
- **作り方**: 1段階目を Phoenix で作り、2・3段階目は1段階目を参照画像にして Nano Banana で「同じ建物が育った次の段階」と指示して作る(きのこハウスで試作済み)。2・3段階目は約26クレジット/枚
- **ちいさな牧場(ranch)**: 動物は描かない(納屋・柵・干し草)。段階を進める指示にも `no animals` を入れる(AIが足すことがある)
- 店・時計の語(bakery / cafe / shop / market / clock)は看板や数字の文字を誘発する。外観を描写して書く

## 未決(素材に影響)

- こびとの見た目・数・役割 / ステージの数 / アプリ名(ロゴ・アイコン) / 町のマスの形
